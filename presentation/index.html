Why Hebrew Idioms?

The Challenge

  • Idioms are context-dependent — same words, different meanings
  • Hebrew adds complexity: rich morphology, prefixed tokens, agglutinative structure
  • No existing Hebrew idiom dataset with dual-task annotations
  • Prior work focuses on English; Hebrew is under-resourced

Core Question

Do transformers learn compositional idiom representations that generalize, or do they memorize specific expressions?

Example: "broke the head"

הוא שבר את הראש על הבעיה

Figurative: "He racked his brain over the problem"

Literal: Actual physical head injury

Models must use context to distinguish meaning — the words alone are identical.

Annotation Format (per sentence)

start_token: 1   end_token: 4
start_char: 4   end_char: 18
base_pie: שבר את הקרח (broke the ice)

Two Supported Tasks

Task 1 — CLS: Binary sentence classification (literal vs figurative) using [CLS] embedding + linear head
Task 2 — SPAN: Token-level BIO sequence labeling + CRF layer. Evaluated with exact-match span F1.

Training Protocol

  • HPO: 15 Optuna trials per model-task (TPE sampling)
  • Seeds: 42, 123, 456 (report mean ± std)
  • CRF layer for SPAN task (valid BIO transitions)
  • AdamW + cosine LR schedule + warmup
  • Early stopping on validation F1
  • Label smoothing (α=0.1) for CLS

Evaluation Metrics

  • CLS: Binary F1 (primary), accuracy, precision, recall
  • SPAN: Exact-match span F1 (primary)
  • 95% bootstrap CIs (10K resamples)
  • Paired t-tests + Bonferroni (α=0.000833)

Prompting Protocol

  • Hebrew instructions, JSON output format
  • Zero-shot and few-shot (k=3)
  • Character-level span matching
  • Single-run evaluations

Infrastructure

  • VAST.ai cloud GPU instances (paid)
  • RTX 4090 (24GB VRAM) for HPO & fine-tuning
  • RTX 5090 for Dicta3 Nemotron self-hosted inference (vLLM)
  • Persistent volume + Google Drive sync
  • Other LLMs via OpenRouter API
  • Local CPU/GPU for evaluation & analysis

Limitations

Statistical

  • 3 seeds → power to detect only Cohen's d ≥ 3.26
  • No pairwise model comparisons reach significance after Bonferroni correction
  • Rankings are observed trends, not validated differences

Scope

  • Hebrew-only — cross-lingual replication needed
  • 60 idioms — small fraction of Hebrew's inventory
  • Single 6-idiom unseen split (leave-one-out not performed)
  • Aggregate unseen performance sensitive to hardest idiom (removing "chased own tail" raises F1 from 0.68 to 0.82)

Methodological

  • No CRF ablation — can't determine if end-bias comes from CRF or encoder
  • Base-size models only (110–125M) — larger models may improve
  • Diagnostics run on subset of models

Prompting

  • Single-run evaluations — no confidence intervals
  • Variance across prompts not measured
  • 4 of 5 LLMs show severe classification bias
  • End-boundary bias hypotheses are post-hoc and untested

Takeaways & Future Work

What We Built

  • Hebrew-Idioms-4800 — first dual-task Hebrew idiom dataset
  • 4,800 sentences, 60 idioms, κ = 0.97
  • Complete benchmark: 6 encoders + 5 LLMs
  • Full analysis pipeline with 35+ figures

Central Finding

Current fine-tuned transformers classify idiomaticity through surface patterns but fail to learn compositional boundary cues that generalize to novel expressions.

Prompting offers a potential alternative for boundary generalization.

Non-Standard CLS Formulation

Our CLS task passes only the raw sentence without the idiom itself — unlike classical idiom identification that provides both sentence + idiom as input. Models must infer idiomaticity from context alone, simulating native language understanding.

Future Work

  • BERT vs LLM with idiom hint — we only tested LLMs with raw sentences (no idiom clue); providing the idiom in the prompt may improve LLM CLS and enable a fair comparison with fine-tuned encoders
  • Cross-lingual replication — does end-bias hold for English, Arabic?
  • CRF ablation — isolate encoder vs CRF contribution
  • Model scaling — larger encoders may improve
  • Hybrid approaches — combine fine-tuning with prompting
  • Leave-one-idiom-out cross-validation
  • Dataset release to HuggingFace for community research
